Configuration

Model providers, GitHub access, themes, and ~/.guided-review/config.json. For rules a team commits to its repository, see Team configuration.

#First run and gr config

The first gr run opens setup, then carries on with your command. gr config (or gr setup) runs it again from your current settings. Nothing is saved until the last step; Ctrl+C leaves without saving. Setup steps:

  1. Color theme: your terminal's colors, or one of 65 themes.
  2. Model provider: setup marks what this machine already has with a ✓, such as a Codex login, an ANTHROPIC_API_KEY, or Ollama running locally. Enter picks a found provider with default models; c opens its details.
  3. Details: the endpoint for a compatible server, the API key (an environment variable, or pasted into config.json), a model for summaries and narration and one for Q&A, and fast mode where it's offered.
  4. Coding agent: what o opens in a chapter: Claude Code, Codex, the Cursor CLI, Gemini CLI, opencode, pi, or a custom command.
  5. GitHub access: only when gh is missing or signed out. See GitHub access.
  6. Finish: setup tests each model and shows how long it took to answer, so a wrong key shows up now rather than mid-review.

Which provider: an Anthropic, OpenAI, or Cursor API key is fastest. These run inside gr, and the Anthropic and OpenAI APIs stream answers. Codex works from your ChatGPT plan with no key, but starts a process per request, so tours are slower.

Provider Default models (summaries / Q&A)
Anthropic API claude-haiku-5-5 / claude-opus-5-5
OpenAI API, Codex gpt-6-luna / gpt-6.1-sol
Cursor Grok 4.7, low effort and Fast / high effort
Claude Code, Bedrock, Vertex haiku / opus

gr config --edit opens the file in $VISUAL or $EDITOR, for settings setup doesn't ask about, such as any model not in its list.

#Reviewing without AI

Choose No AI model in setup ("provider": "none"), or pass --no-agent for one review. Everything works from static analysis except the briefing summary, narration, Q&A, and AI suggestions, and nothing is sent to a model. gr build needs a model. Your previous model settings are kept, so choosing that provider again restores them.

#GitHub access

gr uses the GitHub CLI and your gh auth login by default. Without gh, use a personal access token:

  • Token: create one at github.com/settings/personal-access-tokens. A fine-grained token needs read access to Contents and Metadata, and read and write to Pull requests and Issues. A classic token needs repo (and read:org for private organizations).
  • Where it lives: an environment variable (default GITHUB_TOKEN) or a file with mode 600. config.json stores only the variable name or path.
  • GitHub Enterprise Server: set the API URL to https://<host>/api/v3.

#Fast mode and priority processing

"fastMode": true gives faster answers at a higher price. Setup offers it for Q&A with the anthropic, openai, and codex providers: 

{ "roles": { "qa": { "model": "claude-opus-5-5", "fastMode": true } } }
  • Anthropic API: Anthropic's fast mode, on Opus models only, at roughly double the price. Switching speed invalidates the prompt cache.
  • OpenAI and Codex: priority processing. On a ChatGPT plan it uses up your Codex limits faster.

Other providers ignore it.

#Codex

The codex provider runs codex exec with your codex login. Each run is sandboxed: it can read only the PR worktree and the tools Codex needs, cannot write or reach the network, and ignores your ~/.codex/config.toml, rules, MCP servers, and hooks. This needs a Codex CLI with permission profiles. Set models in Guided Review's config, not Codex's.

#Cursor

The cursor provider runs Cursor's hosted models through the Cursor SDK, with a key from $CURSOR_API_KEY. Cursor's own tools, rules, hooks, and MCP servers are off; the agent gets only the read-only tools the other providers use. Model settings such as effort, speed, and context go in modelParams.

#Color themes

By default gr uses your terminal's colors. It also offers all 65 shiki themes, 21 of them light. A theme colors the whole interface, paints its own background, and is used by diagrams opened in the browser.

Colors mean the same thing everywhere: cyan for keys and selection, magenta for anything the model wrote, green and red for good and bad, and yellow for what needs your attention.

Choose a theme in setup, or press L on the PR list, briefing, or a chapter. The screen previews each theme as you move. / searches (light or dark filters), Enter saves, and Esc restores the one you had. Themes look best with 24-bit color; see Terminals. NO_COLOR turns colors off.

#Config file

~/.guided-review/config.json is written with owner-only permissions. The default, with Codex:

{
  "provider": "codex",
  "model": "gpt-6.1-sol",
  "chapterOrder": "guide",
  "roles": {
    "briefing": { "model": "gpt-6-luna" },
    "narration": { "model": "gpt-6-luna" },
    "qa": { "model": "gpt-6.1-sol" }
  }
}

Model settings

Field Purpose
provider claude-code, anthropic, codex, cursor, openai, openai-compatible, bedrock, vertex, or none.
model The fallback model, used when a role sets none.
roles Per-task overrides for briefing, narration, and qa. See Choose models by task.
baseUrl API base URL for openai-compatible (including /v1) or anthropic. HTTPS, except on localhost.
apiKeyEnv / apiKey The variable holding the key, or the key itself.
effort low, medium, high, xhigh, or max, for Claude and OpenAI models. Setup sets low for briefing and narration to keep tours fast.
fastMode See Fast mode.
modelParams Cursor only: the model variant, such as { "reasoning_effort": "low", "fast": "true" }. Without it, some models default to the expensive Max Mode.
maxOutputTokens Anthropic API output limit per response (default 16000).
toolCalling false for a compatible endpoint that can't call functions. Q&A is then limited to the selected code.

Interface settings (most are also toggled by a key during a tour, which saves them here)

Field Purpose
theme terminal (default) or a shiki theme name, such as nord or github-light.
chapterOrder guide (default), risk, size, or file. Key: f.
hideWhitespace Hide whitespace-only changes (default true). Key: w.
splitDiff Side-by-side diffs (default false). Key: S.
sidebar Show the chapter list on wide terminals (default true). Key: \.
shortExplanation Show only the first lines of each explanation (default false).
glyphs unicode (default) or ascii, for fonts that draw the marks badly.
icons nerd for Nerd Font file icons (default none).
codingAgent What o opens: claude (default), codex, cursor, gemini, opencode, pi, or custom.
codingAgentCommand With custom, the command, such as "aider --message". The prompt goes last, or where you write {prompt}.
github { "tokenEnv": "GITHUB_TOKEN" } or { "tokenFile": "…" }, plus optional "apiUrl". See GitHub access.

A local compatible server without a key:

{ "provider": "openai-compatible", "model": "llama3", "baseUrl": "http://localhost:11434/v1" }

#Choose models by task

A role can set its own model, or a different provider with its own key. This uses Claude Code for summaries and OpenAI for Q&A:

{
  "provider": "claude-code",
  "model": "opus",
  "roles": {
    "briefing": { "model": "haiku" },
    "narration": { "model": "haiku" },
    "qa": { "provider": "openai", "model": "gpt-6.1-sol", "apiKeyEnv": "OPENAI_API_KEY" }
  }
}

A failing role falls back to the top-level model. Claude Code, Bedrock, and Vertex can't be mixed with one another in one run. If no model is available, you get a plain tour.

#Cost

A tour makes one briefing call, then narrates chapters with up to six calls at once; Q&A makes one call per question. To keep large PRs affordable, the briefing prompt is capped, small and low-risk hunks share one summary, lockfiles are sent as parsed package changes, and an interrupted tour resumes where it stopped. Prompt caching is used where the provider supports it. Claude Code, Codex, and Cursor count tours against your plan's limits.

#Debugging model calls

Set GR_DEBUG_MODEL to a file path to log one JSON line per model call, with its role, model, time, and token counts:

GR_DEBUG_MODEL=/tmp/gr-model.jsonl gr review 123

GR_DEBUG_MODEL=1 writes to stderr instead, which mixes into the interface.
